sBot-Datasets: data reference

The detail behind sBot-Datasets: what the ten published repositories contain, how they are structured, how to load them, and how the evaluation in that post was defined and can be re-run.

Figures read from the published repositories on 9 September 2026 · huggingface.co/L5vel

Scope

This page is a snapshot of a growing collection. The counts and figures below were computed from the published repositories on the date above; if more datasets have been added since, treat them as a lower bound and recompute rather than editing by hand.

The subtask spans have mixed processing provenance. Publication receipts classify 897 episodes on the import route: 895 contain 5,201 spans and two contain no spans. Comparing the ten current merged release snapshots with all 32 component outputs matched every one of the 1,499 language_persistent payloads, so these counts describe the release rather than an intermediate export. Component logs show the source spans were read from meta/lerobot_annotations.json without a VLM call. The publishing code preserved all label sequences but cleaned their times: 4,136 of 5,201 starts moved, 4,135 by no more than one 50 Hz frame and one by 0.563 s; ends were rebuilt from the next start and episode end. Those files and receipts contain no field naming the original author or recording human verification, so “import route” must not be read as proof of human authorship.

The other 602 episodes contain 1,681 spans produced on the generation route. Every corresponding component log names Qwen/Qwen3.8-27B; the logs do not retain an immutable model revision. Canonical task strings came from source task metadata. The publishing pipeline used text-only VLM calls for task paraphrases and 5,385 memory rows, and deterministically constructed plan rows from the published subtask sequence. Its component logs also name Qwen3.8-27B, without a pinned revision. These statements describe the released snapshot; intermediate files and evaluation predictions are not counted as released annotations. The L5VEL evaluation uses import-route source references only and excludes generation-route collection components, so it does not measure their quality or training usefulness. The narrative, tool design and findings are in the post.

What every dataset shares

The ten share a common LeRobot schema. The common properties below were checked against all ten meta/info.json files; two metadata differences are called out explicitly.

  • Format. LeRobot codebase_version v3.0 — Parquet shards under data/, MP4 video under videos/, metadata under meta/. Not the older v2.1 layout, and not Lance.
  • Rate. A declared 50 Hz for every stream, state and video alike. Video is H.264, yuv420p, no audio.
  • Cameras. Exactly three per episode: observation.images.left, observation.images.right and observation.images.wrist, each 640×480 RGB.
  • Proprioception. A 10-dimensional observation.state and a matching action: joint1–joint6, gripper, base_x, base_y, base_yaw. In nine repositories, the metadata's names.motors lists only the first seven entries, so it incompletely labels these vectors; base4-plate-croissant labels all ten. A separate 3-dimensional observation.base_pose carries base_x, base_y, base_yaw.
  • End-effector space. A 13-dimensional observation.eef_state and action.eef: Cartesian position, two orientation axes, gripper, and the base pose again. This is what the -eef-merged- in every repository name refers to, and each repository also ships a meta/eef_kinematics.json.
  • Language. Two per-frame columns of LeRobot language dtype, language_persistent and language_events. The subtask spans mix import and Qwen3.8-27B generation routes; memory rows and task paraphrases come from text-only Qwen3.8-27B calls, and plan rows are derived. The paraphrase target was ten alternatives: 1,482 episodes retain ten and 17 retain nine, in addition to the canonical task. See the provenance note.
  • Per-episode flags. meta/episodes/ carries a boolean success per episode, and a per-frame boolean correction is intended to mark teleoperator intervention. It is false on every released frame; this records no marked intervention segments, rather than independently establishing that none occurred.
  • Licence. Apache-2.0 on all ten, none gated, none private. All were last modified on 24 August 2026.

A second structural difference is that five repositories (base4-clean-table, base4-mobile-door, u850-bag-place, u850-fridge-drink and base4-plate-croissant) declare an extra task_index_high_level feature that the other five do not. Treat it as an artifact of the upstream recording pipeline and do not rely on it being present.

Per-dataset table

Every figure is read from the published repositories. Episodes, frames and the task string come from meta/info.json and meta/tasks.parquet; duration is frames divided by the declared 50 fps; the median episode length is computed over that dataset's full meta/episodes/ table; size is the sum of the Hugging Face file tree. Subtasks/ep is the mean number of spans in language_persistent, counted over every episode of that dataset, including the two that carry an empty subtask track. Subtask source comes from the publication-run import/generation receipts and carries the authorship limits stated above. Because all ten share format, rate, cameras, resolution, modalities and licence, those columns are stated once above rather than repeated here.

Cameras and representative frames

Every episode carries three video streams declared at the same 50 Hz as the state: two fixed scene cameras on the robot looking outward, and one camera at the wrist. The scene views give context and the approach geometry; the wrist view can make the contact event easier to see. Changing camera views can introduce a distribution shift; evaluate the views your policy will actually use. The shared declared rate and dataset timestamps do not establish the physical synchronization error between sensors; we have not measured that error.

Annotation density

Subtask counts per episode, and the size of each dataset's subtask-label vocabulary. The vocabulary column is not a proxy for task difficulty — it varies far more than subtask count does; see the next section.

Variation across the collection

The ten datasets share a format, but their annotation is not uniform. Two properties of the published data vary widely and are worth knowing about before you train on the labels or compare datasets to each other.

Label reuse. Distinct subtask strings divided by total spans. Four datasets reuse a small fixed vocabulary (0.006–0.019), five re-word far more freely (0.065–0.304), and base4-mobile-door falls between them at 0.036. At the far end, base4-mobile-place-cup uses 104 distinct strings across 342 spans. Timing granularity. Every span start lands on a frame (a multiple of 0.02 s at 50 Hz). In some datasets about 20% of internal starts also fall on a round tenth of a second — the fraction expected for uniformly distributed positions on a 0.02 s grid — while in others it is 48–72%, which is what a coarser one-decimal timing convention snapped to frames would look like.

The two measures rank the datasets similarly, and that ranking largely follows the recorded processing route: the four import-route repositories occupy the low-vocabulary, roughly 20% tick group; the five generation-route repositories occupy the higher group; and mixed base4-mobile-door lies between them. This association makes provenance a clear confound, but it does not isolate generation from differences in task, source data or preparation. Treat subtask labels as free text, do not assume a single timing convention, and check any desired label vocabulary per dataset.

Getting and using the data

All ten are public and ungated, so no token is needed to read them. The whole collection is 54.9 GB, of which 54.1 GB is video — the Parquet shards come to only 744 MB. If you want the state, actions and language layer but not the pixels, pull just data/ and meta/ and you will move roughly 1.4% of the bytes.

Metadata and annotations only

pip install huggingface_hub pandas pyarrow

hf download L5vel/base4-plate-croissant-eef-merged-v30 \
    --repo-type dataset \
    --include 'meta/**' --include 'data/**' \
    --local-dir ./plate-croissant

That is 34 MB for base4-plate-croissant against 2.5 GB for the full repository. Recovering the segmentation needs only the first frame of each episode, because the persistent track is broadcast across the whole episode: 

import ast, glob, pandas as pd

frames = pd.concat(pd.read_parquet(p) for p in glob.glob("plate-croissant/data/*/*.parquet"))
first  = frames.sort_values(["episode_index", "frame_index"]).groupby("episode_index").head(1)

def subtasks(row):
    msgs = [ast.literal_eval(m) if isinstance(m, str) else m
            for m in row["language_persistent"]]
    return sorted((m["timestamp"], m["content"])
                  for m in msgs if m["style"] == "subtask")

for _, row in first.iterrows():
    print(int(row["episode_index"]), subtasks(row))

Entries may arrive as Python-literal strings or as decoded structs depending on the reader, which is why the snippet handles both. Sort by timestamp rather than trusting list order.

How a subtask span is stored

In the table-cleaning example, “move the green towel towards the mess” starts at 3.94 seconds and the next subtask starts at 9.00 seconds.

The example is episode 104 of base4-clean-table-eef-merged-v30. Its subtask labels were imported from existing annotations; the records do not establish their original authorship or human verification. See the provenance note. The embedded clip in the post is a 25 fps web re-encode of a stream declared at 50 Hz in the dataset.

In the released Parquet row, one of those annotations is stored as this object inside language_persistent: 

{
  "role": "assistant",
  "content": "move the green towel towards the mess",
  "style": "subtask",
  "timestamp": 3.940000057220459,
  "camera": null,
  "tool_calls": null
}

The same persistent message list is attached to every frame in the episode. A reader reconstructs the span by taking this start time and the next subtask start, 9.00 s, giving the half-open interval [3.94, 9.00) s.

Practical notes

  • Disk. Budget the full repository size plus working room. u850-fridge-drink alone is 18.6 GB.
  • Profile video loading. Decoding three 640×480 streams at 50 Hz can be expensive. Profile your loading pipeline before choosing temporal subsampling or camera selection; we have not benchmarked decoding against network transfer.
  • These are v3.0. Tooling written for the v2.1 layout will not read them; convert in the other direction, or use a LeRobot release that speaks v3.0.
  • Check task_index. Nine datasets have a single task string, but base4-mobile-place-cup has two. Read the per-frame index rather than assuming.
  • Use success before training. Five episodes across the collection are flagged unsuccessful; they are shipped, not removed.
  • correction is a per-frame boolean intended to mark teleoperator intervention. All released values are false, so this field provides no intervention segments to filter.

Known limitations of the release

Stated plainly, because they change how the data should be used:

  • The dataset cards are LeRobot boilerplate. All ten still carry “[More Information Needed]” for homepage, paper and BibTeX, and the “visualize this dataset” badge on each card points at a l5vel-peng/… path rather than the published L5vel/… one. The meta/ directory is the authority, not the card prose.
  • The task string and the subtask text can disagree. In episode 82 of base4-mobile-cup the task string says “blue cup” while the subtask text says “black cup”. Check the video and both fields when object identity matters. Label wording and timing granularity also vary widely between datasets; see variation across the collection.
  • Boundary agreement has not been independently measured for this release. No independent repeat annotation or human-validation record is included for the stored spans. There is therefore no measured agreement floor for import-route references and no measured human-review accuracy for the generation-route portion. See the evaluation section for how accurate this kind of boundary placement has and has not been shown to be.
  • language_events is empty. The column exists with the right dtype in all ten, but nothing was written to it. If your loader expects interjections, speech or VQA rows, it will find none.
  • Two episodes carry no subtask spans. One in base4-clean-table and one in u850-fridge-drink have an empty subtask track. Handle the empty case rather than assuming at least one span per episode.
  • No held-out split is defined. Every dataset declares a single train split covering all episodes. Make your own, and make it by episode.
  • People appear in the footage. These were recorded in a working laboratory with the teleoperator and colleagues in frame. Treat them accordingly.

Calibration protocol

L5VEL and RH20T use the same evaluator. The repository retains corpus_a and corpus_b as internal keys for L5VEL and RH20T, respectively; those names are not separate methods. For each task, the preparer sorts SHA-256 hashes of 1729:task:source_id:local_episode and reserves the first ten distinct annotated trajectories. This choice is fixed before model inference and does not inspect label contents or prediction quality. The ten trajectories are put in a seed-only dataset; every other trajectory is put in evaluation-only components. A failed seed is recorded and never replaced.

Each camera configuration uses those same ten identities but makes its own predictions and fits its own parameters. Fits are grouped within task by subtask count, and require at least three complete predictions with the supplied labels in the right order. The study uses count scope, so it assumes the first, second, and later positions represent comparable task phases even when their wording differs. With predicted internal boundary pij, reference boundary gij, and stitched predicted extent Ti, the position correction is: 

offset_j = median_i((p_ij - g_ij) / T_i)

The fitter also stores median reference segment durations divided by Ti. Leave-one-out scoring on the retained seeds selects a duration weight from {0, 0.25, 0.5, 1, 2, 4}. The fit is recommended only when this check gains at least 0.03 temporal IoU and the raw first-boundary mean absolute error is at least 1.5 s. Because the same folds select the weight and estimate its gain, this check is optimistic rather than an independent evaluation.

Accepted parameters are frozen. On a held-out prediction, a dynamic program on a 0.1-second grid shifts all internal boundaries together, balancing corrected model times against the duration pattern while keeping positions nondecreasing. The duration fractions are not renormalized by the calibrator, and a later strict-order cleanup can reject colliding labels. Calibration cannot restore a label omitted by the model. Unsupported subtask counts, rejected fits and failed calibration attempts keep the matching raw prediction. Single-camera calibration applied to 507 of 757 L5VEL trajectories and 659 of 1,305 RH20T trajectories; every fallback remains in the published averages. The public calibration protocol documents the identity maps, hashes and runtime skip reasons.

Evaluation metric definitions

The task the evaluation scores is fixed-label alignment: given an episode's video, the task string, the episode duration and an ordered list of subtask labels with no timestamps, emit exactly that many spans, in order.

Metric definitions, as implemented in the public src/lerobot_align/alignment_metrics.py and evaluation/scripts/score_alignment.py.
MetricBetterDefinition
macro_temporal_iouhigher Mean over supplied labels of the temporal IoU between the predicted span and its reference span. The scorer stitches each placed segmentation to the supplied episode start and end, which can increase IoU without those endpoints being predicted. A missing label still scores 0.
b_hit@3higher Fraction of the internal boundaries placed within 3 seconds of truth. A missing boundary counts as a miss, not as a dropped sample. The 1/3/5-second thresholds are hard-coded, not a command-line knob.
placed_fractionhigher Fraction of supplied labels that received a span at all. A primary metric, not a diagnostic.
boundary_mae_placedlower Mean absolute boundary error over placed boundaries only. It improves when a configuration drops the hard cases, so it is never reported without placed_fraction beside it.

Fixed-label alignment: study and full results

Our 8 September 2026 study evaluated only the fixed-label timing stage. Here, one LeRobot episode is one evaluation trajectory. Each configuration received the task, episode duration and correct ordered subtask labels, without their boundary times. It then had to return one span per label. This does not test whether the tool can discover the right labels. Descriptions, paraphrases, plans, memory, VQA and interjections were also outside the study.

Both evaluation sets used Qwen3.8-27B, two sampled frames per second, a 300-frame limit for the matched high-budget configurations, temperature 0.2, the same scorer and the same task-level aggregation. We fixed ten calibration trajectories per task before fitting and evaluated only on the remainder: 757 trajectories in four L5VEL semantic task groups, and 1,305 trajectories in 39 task groups from the RH20T portion of RoboInter-Data. The L5VEL evaluation combines 16 historical source datasets or configurations into those four task groups; it is not an evaluation of all ten repositories released with the post. The L5VEL evaluation uses only import-route source references; generation-route components in the released collection are excluded. It therefore does not evaluate the quality of those generated subtasks or show whether any released annotation improves downstream training. RoboInter’s public tooling describes ChatGPT preannotation followed by human clip segmentation, cross-checking and sampling-based validation, but it does not report annotator agreement or detailed acceptance statistics in the published workflow.

Temporal intersection over union, or temporal IoU, measures the overlap between a predicted span and its reference, divided by the time covered by either span. Boundary hit rate measures the fraction of internal transitions placed within three seconds of the reference. The fixed episode start and end contribute to IoU but are excluded from boundary hit rate. Scores are averaged within each task and then give every task equal weight.

A missing predicted span scores zero IoU and its boundary counts as a miss. This is what “labels placed” measures in the full results. It does not mean that the tool deletes a supplied reference label from the source dataset. A model call can omit a label or return an invalid timestamp, and strict ordering cleanup can reject a colliding span. Failed outputs stay in the averages with zero placement. A small repeated-label ambiguity made 23 RH20T configuration–trajectory rows unscoreable: six for each single-video configuration, four for each two-view configuration, and three for the 300-frame contact-sheet configuration. Paired comparisons use only trajectories scoreable for both configurations.

Five findings matter when deciding how to use the tool:

  • Native video was stronger than contact sheets in these runs. At the matched 300-frame budget, single-camera video scored 0.513 versus 0.410 for contact sheets on L5VEL, and 0.519 versus 0.327 on RH20T. The paired gains were 0.103 (95% CI 0.042–0.183) and 0.192 (0.160–0.224), and both survived the Holm correction. On RH20T, 4.5% of video outputs failed or were unscoreable, compared with 28.2% for the 300-frame sheets. The shipped 60-frame sheet result is shown separately in Figure R6 because its input budget is smaller.
  • Calibration improved timing on both sets. The table above shows gains of 0.150 and 0.155 on the L5VEL task groups, and 0.042 and 0.047 on RH20T. Both RH20T effects survived the planned 24-test Holm correction. The larger L5VEL effects did not: with only four independent task groups, their uncertainty is much wider than for the 39-task RH20T analysis.
  • The ten examples transfer less reliably on RH20T. Among calibration groups accepted by the fitter, reference boundary positions varied by about 7.6–8.0% of episode duration on RH20T, compared with 2.4% on L5VEL. The calibration-to-evaluation timing shift was about 4.4–4.5% on RH20T and 0.9% on L5VEL. An exact copy of a held-out trajectory’s ordered label sequence appeared among the ten examples for only 9.7% of RH20T trajectories, compared with 94.5% on L5VEL. This weaker coverage and less stable timing are consistent with the smaller RH20T gain; the study cannot separate task diversity, annotation policy and camera observability into individual causes.
  • The seeded timing controls matched the best model on temporal IoU. One control places boundaries at the median relative positions in matching examples. The other takes their median relative segment durations, normalizes them to fill the episode and accumulates them. They scored 0.695/0.696 on L5VEL and 0.591/0.592 on RH20T, compared with 0.687 and 0.566 for calibrated two-view video. These are temporal-IoU point estimates, not a win on every metric: on RH20T the calibrated model’s three-second boundary hit rate was 0.473, slightly above the duration control’s 0.471. The registered comparison did not establish an overall difference after multiple-test correction.
  • We did not establish a benefit from a second camera view. The controlled comparison used uncalibrated single- and two-view inputs. The two-view point estimates were sometimes higher, but the evidence was inconclusive.

The timing controls are deliberately strong. They do not look at video, but they receive the correct label order and the annotated episode start and end, and they always return every label. They test whether a vision model contributes more than the typical timing pattern already present in ten examples. They cannot discover what happened in a new video and should not be read as complete annotation tools.

Several limitations make the calibration numbers less clean than we would like. Calibrated and uncalibrated configurations made separate model calls at temperature 0.2, so their difference includes response variation as well as the calibration transform. The RH20T estimates are exploratory because its protocol was revised after a preliminary null result, with changes expected to help calibration; they are not an independent confirmation. We also lack a human-to-human agreement measurement for either set. In addition, the component-wise median duration fractions are not renormalized: accepted priors sum to 0.972–0.999 on L5VEL and 0.858–1.117 on RH20T. The same three to ten usable seeds select the duration weight and estimate its leave-one-out benefit, and the fitter’s bias gate checks only the first boundary. These choices can make a small-sample fit optimistic or unstable. The run manifests do not pin an immutable model-weight revision, which limits exact runtime replay.

These results support using fixed-label video alignment to draft boundaries for human review. The model did not outperform the seeded timing controls on temporal IoU, so this study does not establish that video adds timing accuracy beyond a task’s ten-example prior. It also does not evaluate automatic label discovery. The metric definitions give the exact scoring rules.

Native video reduces Qwen’s visual-token workload

We compared the two frame formats using the pinned geometry of the official Qwen3.8-27B processor. For every trajectory, we derived both format counts from the same wrist-camera timestamps using the pinned processor geometry: two frames per second, at most 300 frames, resized to 224 pixels wide. The only difference was whether those frames became 5×4 contact sheets or one native video. The census covers all 2,062 held-out evaluation trajectories: 757 from L5VEL and 1,305 from RH20T.

We count visual tokens as Σ product(grid_thw) / merge_size², using image_grid_thw for the sheets and video_grid_thw for video. Qwen’s official video processor configuration uses 16-pixel spatial patches, merges them 2×2, and groups video frames in temporal pairs. Contact sheets also pay for a complete 5×4 canvas when their last sheet is only partly filled. Together, these choices explain the reduction here; changing the sampling rate, resolution or sheet layout can change it. Qwen’s model card documents native image and video input and configurable processor budgets. It does not itself claim that video is always cheaper than contact sheets.

We checked the metadata-derived census against decoded pixels. Six examples at fixed short, median and long frame-count ranks had processor grids and visual placeholders that matched the census exactly; both representations also completed in 12 local Qwen3.8-27B requests. This validates the counting path and payload compatibility, not total cost or throughput. Hardware and run-manifest details are in the reproduction notes.

This is a visual-token result. It does not measure generated tokens, billing, latency or annotation accuracy, and native video adds timestamp text around its visual tokens. Figure R6 reports accuracy separately. We exclude server token telemetry because the available vLLM counters treated the two modalities inconsistently and therefore cannot support a cross-format comparison. The reproduction notes describe the scripts, validation and limits.
